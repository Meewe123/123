# Orbital Rush — полный контекст

Документ для обсуждения игры с ИИ. Самодостаточный: читающему не нужен доступ
к коду. Все числа взяты из текущего состояния репозитория (версия 1.3.0,
коммит `cc488bd`, ветка `claude/app-store-game-ov8fwj`).

Играбельная сборка: <https://claude.ai/code/artifact/04b6a2c8-8bd1-4e94-8d60-faaf6ea954e6>

---

## 1. Что это

Мобильная аркада «в один палец». Игрок — шар, вращающийся по орбите
фиксированного радиуса вокруг центральной звезды. Единственное управление —
тап: он разворачивает движение в обратную сторону. Извне к центру сжимаются
кольца; в каждом есть одна или несколько щелей. Кольцо доходит до орбиты —
либо ты в щели, либо забег окончен. Каждое пройденное кольцо = 1 очко.

Жанр: endless-раннер на реакцию и точность, родня *Super Hexagon*, *Duet*,
*Twist*. Сессия — от 20 секунд до пары минут.

Позиционирование: игра не про «уворачиваться», а про **выбор** внутри
уворачивания. Ниже это ключевое.

---

## 2. Ядро: SAFE или GREED

В щелях лежат орбы. Генератор ставит каждый орб на измеренном расстоянии от
безопасной линии (центра щели):

- **safe-орб** — близко к центру, взять почти ничего не стоит;
- **greed-орб** — далеко к краю, взять его съедает бóльшую часть запаса; платит
  вдвое больше осколков и даёт два звена цепочки вместо одного.

`risk` орба — доля свободного места щели (`ring.slack`), а не абсолютная
величина, поэтому тесное кольцо физически не может предложить жадный орб,
на который у него нет места.

Распределение риска намеренно бимодальное: с вероятностью 0.45 берётся
`risk ∈ [0.55, 1]`, иначе `risk ∈ [0, 0.35]`. То есть кольцо либо задаёт
вопрос, либо явно даёт выдохнуть — а не мямлит.

**Цепочка (chain).** Каждый собранный орб добавляет звено (safe +1, greed +2).
Каждые 6 звеньев — ступень множителя, максимум x8. Пропустил орб на кольце,
где он был, — цепочка обнуляется.

**PERFECT.** Пройти щель ровно по середине. «Середина» — не метафора: у каждой
щели нарисовано окно шириной `±(1 − perfectThreshold) × полуширина щели`, и
судится ровно оно. При `perfectThreshold = 0.78` окно — это средние 22% от
полуширины.

**Связка, которая делает игру игрой.** PERFECT *спасает* цепочку, если
пропущенный орб был жадным. То есть недостижимо далёкий greed-орб перестаёт
быть чистым убытком: можно отказаться от него и продеть кольцо по центру —
цепочка выживет. Safe-орб всегда достижим, поэтому его пропуск точностью не
оправдывается.

Окно PERFECT специально уже, чем максимальный вынос жадного орба: замерено —
46% greed-орбов лежат вне окна, safe-орбов вне окна 0%. Значит «жадная линия»
и «линия точности» — это два разных пути, а не один.

## 3. Геометрия и честность

Это часть, которую переписывали трижды, потому что игрок жаловался «я прохожу
сквозь стены».

**Кольца параметризованы пройденным путём (travel), а не временем.** Вращение,
пульсация и дрейф щели — функции того, насколько кольцо продвинулось внутрь.
Поэтому точное состояние кольца в момент встречи с орбитой известно уже при
его рождении, как бы ни менялась скорость игры между этими моментами.

**Коллизия непрерывная.** Кольцо касается игрока не в одной точке, а на целой
полосе travel (радиус игрока + половина толщины кольца). Эта полоса
просматривается с фиксированным шагом `BAND_SAMPLE = 0.0025` **в travel**, а не
по кадрам. Отсюда: вердикт одинаков на 60 Гц, 120 Гц и в headless-Node.
Что визуально касается тебя — то и убивает.

**Игрок — круг.** Один радиус `playerRadius = 0.034`. Раньше это была «линза»
(узкая по радиусу, широкая по касательной) — выглядело как фрисби и означало,
что одна ось тайно добрее другой. Сейчас нарисованная заливка в точности равна
телу коллизии; чернильный контур рисуется снаружи заливки.

**Инвариант проходимости.** Из (1) и (2) генератор умеет вычислять для каждого
кольца:

- минимальную ширину щели, в которую заметаемое тело игрока физически влезает:
  `PLAYER_HALF + sweep/2 + gapMargin`, где `sweep` учитывает, что за время
  пересечения игрок продолжает вращаться, кольцо — крутиться, а щель — дрейфовать;
- дугу, до которой игрок ещё может дотянуться от края предыдущей щели
  (не от её центра — это была отдельная ошибка).

Генератор отказывается выпускать что-либо теснее. Непроходимых колец не бывает
по построению; сложность растёт скоростью, вращением, числом щелей и
особенностями зон.

**Орбы лежат в той щели, на которую нацелено кольцо.** Это был реальный баг:
орб ставился в случайную щель, а прицел был на другой, и на двухщелевых кольцах
safe-орб оказывался в ~π радиан от единственного достижимого прохода. 179 из
1030 таких колец рвали цепочку без вины игрока.

## 4. Числа (текущий TUNE)

Все размеры в «единицах поля»: 1.0 = половина короткой стороны экрана.

| Параметр | Значение | Смысл |
| --- | --- | --- |
| `viewScale` | 1.12 | камера; потолок — правило, а не вкус (см. ниже) |
| `playerOrbit` | 0.44 | радиус орбиты игрока |
| `playerRadius` | 0.034 | радиус шара = тело коллизии |
| `ringThickness` | 0.024 | толщина кольца |
| `orbRadius` | 0.026 | радиус орба |
| `spawnRadius` | 1.30 | где рождаются кольца |
| `playerAngularSpeed` | 2.35 рад/с | базовая скорость вращения игрока |
| `ringSpeed` | 0.48 | базовая скорость схождения колец |
| `baseSpacing` / `minSpacing` | 0.42 / 0.38 | расстояние между кольцами (≈0.88 с → 0.79 с) |
| `gapMargin` | 0.15 рад | запас сверх геометрического минимума на реакцию |
| `reachSafety` | 0.85 | какую долю достижимой дуги генератор реально использует |
| `greedThreshold` | 0.45 | с какой доли `slack` орб считается жадным |
| `greedBonus` | 2 | множитель выплаты за жадный орб |
| `orbReach` | 0.85 | максимальный вынос орба как доля `slack` |
| `perfectThreshold` | 0.78 | окно PERFECT = средние 22% полуширины щели |
| `comboPerMultiplier` | 6 | звеньев на ступень множителя |
| `maxMultiplier` | 8 | x8 = OVERDRIVE |
| `orbChance` | 0.66 | доля колец с орбом |
| `shieldFirst` / `shieldEvery` | 10 / 15 | расписание щитов |
| `shieldCharges` | 2 | щит съедает два кольца |
| `powerupEvery` | 11 | слот для slow-mo / x2 между щитами |
| `reviveCost` | 150 | цена одного оживления за забег |
| `zoneLength` | 14 | колец на зону |
| `deathHold` | 0.75 с | длительность смерти до экрана итогов |

**Потолок камеры — это правило.** Кольцо, которое надо пройти следующим, стоит
на `playerOrbit + baseSpacing = 0.86`, и оно должно быть целиком на экране в
момент, когда ты проходишь текущее (щель может оказаться под любым углом, в том
числе там, где экран обрезает). Отсюда `viewScale ≤ 1 / 0.86 = 1.163`. Стоит
1.12 с запасом; на это есть тест.

**Сложность:** `difficultyAt(score) = 1 − exp(−score / 95)`, 0..1. Влияет на
скорость схождения, скорость игрока, расстояние между кольцами и желаемую
ширину щелей.

## 5. Зоны

Восемь зон по 14 колец, дальше цикл (счётчик «круга» продолжает расти).
У каждой свой генератор, палитра, частицы, эффект PERFECT и тембр синтезатора.

| # | Зона | Щелей | `gapHalf` | Вращение (рад/с) | Особенность | Эффект PERFECT |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | FLOW | 1 | 0.85 | 0.30–0.60 | — | pulse |
| 2 | VOLTAGE | 1–2 | 0.72 | 0.45–0.85 | направление чередуется | arc |
| 3 | INFERNO | 1–2 | 0.70 | 0.50–0.95 | каждое 3-е кольцо — двойное | burst |
| 4 | FROZEN | 2 | 0.62 | 0.40–0.80 | кольца пульсируют по радиусу | shatter |
| 5 | DRIFT | 1–2 | 0.66 | 0.55–1.00 | щель дрейфует по кольцу | warp |
| 6 | GHOST | 1 | 0.70 | 0.60–1.00 | кольцо проявляется поздно | echo |
| 7 | STORM | 2 | 0.45 | 1.05–1.55 | самое быстрое вращение | lightning |
| 8 | VOID | 1–2 | 0.55 | 0.80–1.30 | дрейф + чередование, темнота | void |

`gapHalf` — это **запрос**, а не гарантия: генератор поднимает его до
вычисленного минимума, если запрошенного не хватает. На высокой сложности
STORM и VOID почти всегда упираются в минимум.

## 6. Экономика и прогрессия

**Одна валюта — SHARDS (осколки).** Зарабатываются только игрой: орбы платят
`множитель × (жадный ? 2 : 1)`, PERFECT платит +1.

Замеры на боте (автопилот, который используется и в демо на титуле, и в
тестах), с «человеческой» неточностью:

| Дошёл до кольца | Осколков | Множитель |
| --- | --- | --- |
| 30 | ~88 | x4 |
| 60 | ~170 | x6 |
| 120 | ~370 | x3–4 |

Почти идеальный бот за длинный забег (медиана 912 колец): ~2900 осколков,
x8 достигается в 38 из 40 забегов, медиана — на 71-м кольце, ~10 обрывов
цепочки за забег.

**Траты:** скины 300 / 550 / 850 / 1200 / 1700 / 2400, следы 400 / 700 / 1100,
эффекты 350 / 650 / 1000. Весь каталог за осколки ≈ 11 200. Оживление 150.

**Достижения** — 12 штук, каждое объявлено как метрика против цели (поэтому на
главном экране можно показать «7 / 10», а не «ещё нет»). Три скина, два следа и два
эффекта открываются только достижениями и не продаются никогда.

**Ежедневное:** миссии (3 в день, из 9 шаблонов), серия дней со вехами
(3 / 7 / 14 / 30 дней), ежедневный забег с сидом, выведенным из даты — у всех
в мире сегодня одни и те же кольца. Бонус за первый забег дня выдаётся молча,
без всплывающего окна и без «зайди, а то потеряешь».

## 7. Режимы и экраны

- **Endless** — основной.
- **Daily Run** — детерминированный сид от даты, один зачётный забег в день,
  повторы — тренировка (свой личный рекорд улучшать можно).
- **PRACTICE** — удар стоит цепочки, а не забега. Тот же генератор, та же
  коллизия, те же кольца: режим, который играется иначе, учил бы неправильному
  таймингу. Не копит **ничего** — ни очков, ни осколков, ни миссий, ни серии, —
  и говорит об этом на экране всё время, пока длится.
- **Challenge** — код вида `1-e-<seed36>-<score36>` в ссылке: получатель играет
  ровно твой сид с твоим счётом как целью. Без сервера.
- Экраны: титул (с «ближайшей целью»), пауза, итоги забега, ежедневка,
  профиль/коллекция, магазин, настройки.

**Обучение** — не туториал, а короткие строки-подсказки по одной за раз,
каждая показывается один раз в жизни профиля, и новая никогда не затирает ту,
что ещё на экране.

## 8. Что сделано и чего сознательно нет

Прямые ограничения заказчика, которым код следует:

- **Никакой рекламы.** Вообще. В проекте нет ни одного рекламного SDK,
  и нигде нет «посмотри ролик, чтобы продолжить».
- **Никаких лутбоксов, энергии, таймеров, батлпасса, второй валюты.**
- **Никаких фейков.** `LeaderboardService.isGlobal === false`, и интерфейс
  честно пишет «YOUR RECORDS», потому что сервера нет. `PurchaseService.available
  === false` — и именно поэтому два премиум-скина **вообще не показываются**:
  ни в магазине, ни в счётчике коллекции. Вещь, которую никто не может купить,
  хуже, чем её отсутствие. Обе службы — интерфейсы, под которые бэкенд
  подставляется без изменения геймплея.
- **Никакого Game Center.** Это потребовало бы GameKit и Apple-аккаунта, что
  лишило бы приложение ярлыка *Data Not Collected*.
- **Никакой сети, аналитики, аккаунтов.** Игра полностью работает в
  авиарежиме; всё, что открыто, лежит на устройстве.

Дополнительно:

- **Доступность:** у каждого пикапа свой силуэт (осколок — круг, щит —
  шестиугольник, слоу — квадрат, x2 — ромб), то есть они различимы вообще без
  цветового зрения; отдельная настройка добавляет им жёсткий тёмный контур.
  Есть режим «меньше эффектов» (не меняет геймплей) и уважение к
  `prefers-reduced-motion`.
- **Цвет щита зарезервирован.** `#2f9bff`. Ни один скин не подпускается ближе
  40° по тону, орбы отталкиваются и от скина, и от кольца, и от щита
  одновременно. Щит — единственное, что означает «ошибку можно пережить»,
  поэтому опознаётся мгновенно и один раз.

## 9. Архитектура

Ноль зависимостей в рантайме. Чистые ES-модули, без движка, без фреймворка,
без сборщика (сборщик есть только для однофайловой версии).

```
www/src/
  engine/   loop (фикс. шаг 1/120 с), input, audio, fx (пулы), storage,
            rng (mulberry32), util, haptics
  game/     world (симуляция), config (все числа), render (canvas),
            palette (разведение тонов), effects, autopilot, meta, daily,
            achievements
  services/ leaderboard, purchase, challenge      ← интерфейсы под бэкенд
  ui/       ui (DOM), sharecard (canvas 1080×1350)
  main.js   склейка и конечный автомат режимов
```

~6 200 строк JS. Однофайловая сборка — 278 КБ одним HTML.

**Детерминизм.** `World` не знает про DOM и про часы: состояние выводится из
(сид, тапы, dt). Поэтому забег воспроизводим, тестируем headless и
фаст-форвардится в Node. Фиксированный шаг 1/120 с с аккумулятором и защитой
от «спирали смерти».

**Звук** синтезируется целиком на WebAudio: ни одного аудиофайла. У каждой зоны
свой тембр (осцилляторы, фильтр, баланс слоёв), темп и яркость ведутся
«интенсивностью» забега.

**Графика** — canvas 2D. Свечение сделано послойными обводками, а не
`shadowBlur` (выглядит так же, стоит долю от филлрейта). Градиенты, палитры и
буферы щелей кэшируются; частицы, волны и всплывающий текст лежат в пулах —
во время игры не аллоцируется ничего.

**Иконки и сплэш** генерируются кодом (`tools/make_icons.py`, свой SDF-рендер и
свой энкодер PNG на одном zlib).

**Нативная обёртка** — настоящий Xcode-проект (`ios/`, Capacitor 8, Swift
Package Manager, без CocoaPods), `PrivacyInfo.xcprivacy` подключён.

## 10. Что удерживается тестами

79 headless-тестов, 66 проверок в браузере, 11 проверок однофайловой сборки.
Важны не количества, а то, что именно это — свойства честности, а не обещания:

- ни одно кольцо не уже, чем игрок физически может проехать;
- каждая щель достижима из **любой** точки предыдущей щели, не только из центра;
- игрок никогда не выживает, перекрывая стену (проверяется прогоном забегов);
- каждый орб — включая жадный — собираем чистым проходом;
- каждый орб лежит в той щели, на которую нацелено кольцо;
- жадные орбы и центр — разные линии (25% < доля вне окна < 75%);
- метка PERFECT, которую рисует рендер, — та же, которую судит симуляция;
- следующее кольцо целиком на экране в момент прохода текущего;
- тело коллизии — круг (обе полуоси выводятся из одного радиуса);
- ни один скин не ближе 40° по тону к синему щиту; метка скина читается на
  собственном теле (по контрасту либо по контуру);
- сохранение переживает порчу, частичность и миграцию со схемы v1;
- версия совпадает в `package.json`, в экране настроек и в Xcode-проекте;
- сервис-воркер кэширует каждый реально отгружаемый файл;
- в магазине нет лутбоксов/таймеров/«осталось N» (проверяется текстом).

## 11. История правок геймплея (что уже пробовали)

Полезно, чтобы не предлагать откат к тому, что уже отвергли:

1. **«Прохожу сквозь стены»** — коллизия судилась в один момент времени.
   Замерено: 143 из 488 колец задевались, смертей 0. Починено непрерывной
   полосой + телом-линзой + вычисляемым полом ширины щели.
2. **Непроходимые щели** — кольца были параметризованы временем. Переписаны на
   travel, чтобы генератор мог целиться.
3. **Игрок невидим** — линза была 3.5 px. Пересчитана геометрия.
4. **Дыра в достижимости** — мерили от прицельного угла, а не от дальнего края
   предыдущей щели.
5. **Микропауза на PERFECT** (hit-stop) — сбивала поток, убрана целиком.
6. **«Призрак» лучшего забега** — второй полупрозрачный игрок, удалён по
   просьбе.
7. **Фрисби вместо шара** — линза заменена кругом; затем «отрендеренная сфера»
   заменена плоским мультяшным шаром (плоский цвет, чернильный контур, тёмный
   серп, один блик).
8. **Слишком далеко** — добавлен `viewScale`, кольца стали толще, центральное
   ядро уменьшено (оно было крупнее и ярче игрока, и глаз читал не тот объект).

## 12. Известные ограничения и открытые вопросы

Это то, о чём имеет смысл спорить:

1. **Нет сервера.** Нет глобальных таблиц, нет кросс-девайсного прогресса, нет
   «челленджа друга» иначе как через ссылку с кодом. Архитектура готова
   (`LeaderboardService`), решение — продуктовое: сервер = аккаунты = приватность
   и стоимость.
2. **Монетизация фактически нулевая.** Два премиум-скина существуют в коде, но
   скрыты, пока нет платёжного моста. Что честно продавать в игре, которая
   принципиально без рекламы и без pay-to-win — открытый вопрос.
3. **Баланс мерится ботом, не людьми.** Все числа выше — из автопилота с
   добавленной «неточностью». Это хороший инструмент для инвариантов и плохой
   для ощущения. Нужен живой плейтест.
4. **Длина сессии.** Медиана бота ~900 колец; человек, вероятно, 30–150. Кривая
   сложности (`exp(−score/95)`) настроена так, что интересное начинается
   довольно рано, но проверить это без людей нельзя.
5. **x8 / OVERDRIVE.** Сейчас это пик, который надо заслужить (бот — 71-е
   кольцо). Возможно, для массовой аудитории его надо показывать раньше и чаще.
6. **Ретеншн-петля.** Есть ежедневка, серия, миссии, достижения, коллекция и
   «ближайшая цель» на титуле. Нет ничего, что *давит* (нет «зайди или
   потеряешь»). Вопрос: достаточно ли этого, и что добавить, не нарушив запрет
   на тёмные паттерны.
7. **Виральность.** Есть карточка результата (рисуется в canvas) и коды-вызовы.
   Нет записи повтора, нет видео, нет привязки к соцсетям.
8. **Локализация.** Всё на английском, строк мало (интерфейс почти без текста),
   но словаря нет — строки зашиты в разметку и код.
9. **Один жест.** Управление — только тап-разворот. Ни свайпа, ни удержания.
   Это осознанное ограничение жанра; расширение изменило бы игру.

## 13. Как это запустить

```bash
npm install      # только dev-инструменты; у самой игры зависимостей нет
npm run dev      # http://localhost:8080
npm test         # 79 headless
npm run test:e2e # 66 проверок в браузере
npm run verify   # иконки + всё вышеперечисленное + однофайловая сборка
```

Клавиатура на десктопе: **пробел / ← / →** — разворот, то же самое, что тап.
